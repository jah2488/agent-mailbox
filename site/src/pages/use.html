Day to day

Use it

You mostly use agent-mailbox by talking to Claude Code. The mailbox command is for setup, the daemon, and the numbers.

Ask a teammate's agent

Ask the way you'd ask a person:

Ask Robin's Claude whether the staging deploy is green, and what's blocking the release.

Your agent drafts an ask, and Claude Code shows you the exact text before it goes. You can keep working while you wait. When the reply arrives, Claude Code mentions it at the start of your next prompt, and your agent reads it to you.

What your agent can do in Claude Code
ToolWhat it's for
mailbox_sendAsk, reply, promise, fulfil or break. Always asks you first.
mailbox_receiveRead new mail, optionally only replies to one ask.
mailbox_threadThe whole conversation around one message.
mailbox_peersWho you're connected with.
mailbox_promisesWhat you've promised, and what you've been promised.

When mail arrives

Your agent gets each message with the teammate's text marked as untrusted. After it, outside the marked text, agent-mailbox adds one line saying what the message needs from you:

  • Needs you A teammate asked you something. Your agent offers to draft a reply, and sends nothing until you approve the exact text.
  • Next A teammate sent something to act on, such as a skill or a script. Your agent shows it to you and asks before it installs, runs or changes anything.
  • FYI A hello, a promise, or news about a promise. Your agent passes it on.
Why the marking matters

A teammate's agent can be wrong, and a teammate's machine can be compromised. Your agent tells you what the marked text says, and doesn't follow instructions in it.

Promises

When you can't answer yet, your agent can promise to. A promise names the ask and the item, and can add a condition and a due date, such as "the prod keys, once the release ships, by Friday." Later your agent sends fulfil or break for the same item. Each one is an ordinary send, so it asks you first.

Once a day, Claude Code mentions any promise you made that's overdue or has gone 30 days with no due date. mailbox promises lists them all.

Let your daemon answer

With the daemon on, teammates get answers while you're away. It reads only ~/.agent-mailbox/share/, and handles each part differently.

The share folder
WhereWhat the daemon does
share/status/Answers from it.
share/notes/May answer from it, and flags that answer for your review.
any file named secret or privateNever reads it.
everything outside share/Can't see it.

The rules live in ~/.agent-mailbox/policy.cedar. After you edit them, mailbox policy sign signs them with your root key. Without a valid signed policy, the daemon answers nothing and defers every ask to you. A tool-less claude -p drafts each answer from the allowed files only.

When it can't answer, a draft looks like it holds a secret, or something fails, it sends a short "waiting for you" reply instead. The asker sees only that. mailbox review shows you the reason.

Review and measure

mailbox review lists what the daemon deferred or flagged. Below that, it lists each answer you haven't graded yet, with the question and the daemon's reply. Once you grade them, mailbox stats scores the daemon against a 70% bar.

mailbox review
mailbox grade <ref> right
mailbox stats --since 14d
