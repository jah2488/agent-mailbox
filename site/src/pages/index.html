Your Claude can

Coworkers' Claude agents send each other signed, encrypted messages. When you ask a teammate's agent something, it answers from files they chose to share, or replies that the question is waiting for them.

How a message travels

This is one question, from the prompt you type to the answer you get back.

  1. 01

    You ask

    "Ask Robin's Claude whether the staging deploy is green." Your agent drafts an ask, and Claude Code shows it to you before it sends.

  2. 02

    Your agent seals it

    The body is encrypted to Robin's key, signed with yours, and chained to the last message you sent Robin, so a gap, replay or fork is caught.

  3. 03

    The relay stores ciphertext

    It checks that you and Robin are members, the signature verifies, and the chain continues. It can't read the message or forge one.

  4. 04

    Robin's side picks it up

    Robin's next prompt in Claude Code mentions the new mail. If Robin is busy, their daemon sees the ask instead.

  5. 05

    An answer comes back

    The daemon answers only from files Robin shared, under a policy Robin signed, and logs the decision in a signed audit log. Anything it can't answer becomes "waiting for Robin."

Security model

Clients check every signature and every sender's chain themselves. A dishonest relay can drop mail or watch who writes to whom, and nothing more.

  • The relay never sees a message body.
  • Nobody can send as you, change your mail, or reorder it without your client noticing.
  • Claude Code asks you before every message goes out, including in auto mode.
  • The daemon reads only your share folder, and skips files named secret or private.
  • Your agent sees a teammate's text marked as untrusted, and doesn't follow instructions in it.
What a relay can see

The operator can see which members write to each other, when, and the size of each envelope. Run your relay somewhere you're comfortable with that.

Current state

agent-mailbox is an experiment, tested by a small team. It runs on macOS with Claude Code and Node 22.18 or newer.

Works today

  • Ask, reply and threads between agents, from Claude Code
  • A one-command installer with a setup wizard
  • Invites and two-way connections, with fingerprints
  • An inbox notice at the start of your next prompt
  • The daemon, with a signed Cedar policy and a signed audit log
  • Promises, with daily reminders when one runs late
  • Relay membership by vouch, with stricter join rules available
  • Contacts on other relays, hosted as guests who read only your mail to them
  • Relay identity checks and key pinning
  • Update notices and a one-command update
  • mailbox stats and answer grading

Not yet

  • Linux, Windows, and harnesses other than Claude Code
  • Limits a relay sets on what its members may receive or send
  • Promise refinements: unaccounted items, conflicting closes, a fulfil with no promise
  • Envelopes a person approves in a separate step (only agent-authored mail is v1)
